# Fable：是否去掉 dtmoe 和 TOT（12:04:19–12:05:20，0.48 美元）

**决定：选 C —— 去掉 TOT，保留 dtmoe（dtmoe 可按下面方式降成本）。**

**支持证据**
- TOT 无官方代码，纯靠论文复现，且改造本身已是登记偏差（逐步 identification 项、head 接 latent）。即使跑出来，审稿人也能质疑"这不是 TOT"；门槛 (a)(b) 还没过，登记里本来就写了"未过门槛则报 skipped"，去掉它是执行既定规则，不是新决定。
- dtmoe 相反：有官方代码（ICML 2026），机制是专家增删 + 时序记忆路由 + 漂移检测，是表 1 里与 MICE "混合专家 + 记忆" 最近的对手。六个 TS 基线里只删它，最像藏基线。论文规则是"现象保证第一，SOTA 第二"，dtmoe 输赢都无所谓，但缺席有所谓。
- 成本：去掉 TOT 省 ~290–490 GPU-h；dtmoe 剩 ~250–450 GPU-h，8 张 A800 约 1.5–2.5 天，可承受。

**替代方案**
- 降 dtmoe 成本（需修正案）：① 砍 drift_k_sigma 轴只用默认 2（dev 约减 2/3）；② 不用 strict deterministic，改固定 seed + 默认 cuDNN，并在附录注明 GPU 非确定性（这是 40× 慢的来源）。我推荐 ①，② 若用户接受也可。
- A（两者都删）可行但弱：删 dtmoe 要给理由，"成本"对最相关对手不够。D 不建议：4 个 CPU 基线便宜且已登记。

**论文表述**（避免"藏基线"）：表 1 脚注 + 附录一句："TOT（NeurIPS 2025）无公开代码，预登记要求先通过复现门槛再改造；门槛未执行，按登记规则不纳入。该决定记录于 2026-10-20 修正案，作出时未读取任何 TOT 或 dtmoe 分数。" 关键是日期 + "未读分数"，写进 AMENDMENT 并提交。

**主要风险**：dtmoe 的 RevIN 去均值可能吃掉类别信号，跑出很差的数字反被质疑 strawman（已在 README 登记为已知 handicap，附录要重申并给机制触发计数）。

**置信度**：中高（0.7）。

**需用户批准**：是 —— 删除已登记基线属于协议变更；若同时砍 dtmoe 网格或放弃 strict 模式，需作为同一修正案一并批准。
