# Fable：TOT 开发网格超出成本上限（11:3x，0.23 美元）

**决定**：选 B——TOT 开发网格与测试全部迁到 A800（确定性模式），先做资格测试再正式跑；若资格测试显示 GPU 加速 <5× 或总 GPU 成本投影 >300 GPU-h，则退回 C（不跑，报告"因成本未运行"，gate (a) 照常）。
**支持证据**：(1) A 实际不可行：测试集 covertype（d=54）单任务 3–12 天，超过 7 天作业上限，即使开发网格跑完测试也完不成；且 2400 CPU-h 已超注册上限 1500，加上 >3000 CPU-h 的 stage 2 会挤占 P1/P3/P4 的 500 核。(2) 成本瓶颈是 vmap(jacfwd) 的 d² 项，正是 GPU 批量雅可比最擅长的部分；TOT 模型极小，一张 A800 可并排 4–8 个任务（显存远低于 28 GB 规则），有效 GPU 成本约为 2400/10/4 ≈ 60–120 GPU-h（开发）+ 同量级（测试），对 600–1200 GPU-h 预算影响可控。(3) gate (a) 已因发布代码需 CUDA 迁到 GPU（commit 8a6009f），开发/测试同在 GPU 反而设备一致。
**备选**：A 仅在"不跑 d≥50 的测试流"时可行，但会在主表留空；C 最便宜，但 TOT 是已注册的调参基线，若 TKDE 审稿人点名要求 TOT，缺席需额外解释。
**关键风险**：GPU 加速未实测（低 d 如 elec2 可能因 kernel 开销不快，但其本身便宜）；GPU 与 CPU 数值差异——资格测试须用 elec2 L16 s1 对比 CPU 结果在容差内，并固定 `torch.use_deterministic_algorithms(True)`；并排多任务需验证互不干扰吞吐（util ≥90%）。
**置信度**：中（约 65%）——结论依赖"GPU 加速 ≥10×"这一未测假设，资格测试后可升至高。
**需用户批准**：是。注册文件明确规定超 1500 CPU-h 的决定权归用户；且 B 改变了开发网格的运行设备（注册写的是 CPU），属于注册偏离，需在 AMENDMENT 中记录并由用户签字。
