**Overall:** The amendment's substance matches `codex_nondeterminism.md` on every mandatory point: the stop is preserved, the three outputs are kept, the classification string is verbatim ("non-reproducible; unresolved by bit comparison"), the exception is narrow and explicit (dtmoe only), there is no blanket nondeterminism exemption, remaining stages resume only after a fresh canary with monitoring and failure stops unchanged, dtmoe is deferred to an H800 rerun under strict determinism (flags exactly as specified, `CUBLAS_WORKSPACE_CONFIG=:4096:8` before CUDA init), qualification is by fresh-process duplicates rather than flags alone, and the no-derived-tolerance clause is present with a prospectively registered fallback (equal replication budget, seeds, aggregation, tie-breaking). One deliberate scope extension — discarding the CPU dtmoe results and rerunning "all paper results" — comes from the user decision and is attributed as such, not from the arbiter; that is legitimate but rests on the user record, not on `codex_nondeterminism.md`. The findings below are enforcement and specification gaps.

### Findings

**1. P1 / Confirmed issue — The amendment's "dtmoe stage ends here" is not enforced by `verify_chain.sh`, and default re-invocation would destroy preserved evidence.**
- Location: AMENDMENT_20261018b.md:15-16 (change 1) vs. verify_chain.sh:27, :37-39, :50, :79.
- Evidence: `verify_chain.sh:79` defaults to `canary dtmoe confirm_cp r14_confirm probs_gen cp_gen`; `dtmoe()` at :50 skips a stem only if `$V/cmp/dtmoe/$stem.txt` exists, but on mismatch `task()` moves the comparison to `$cm.DIFF` (:37) and halts — so the mismatching task-15 stem has no `.txt` and will not be skipped. `clean()` (:27) then `rm -f`'s `<stem>.npz/.pkl/.closes.pkl/__probs.npz/.ckpt*` in `$V/dtmoe_dev/P` before re-running — deleting the first replay's preserved task-15 outputs, one of the three outputs the amendment (line 12) and the arbiter ("Preserve the stop and all three outputs") require kept. Resumption also requires deliberately clearing `$V/CHAIN_STOP` (gate, :13-14), after which a habitual bare `verify_chain.sh` triggers exactly this path, and would additionally replay tasks 16-38 that the amendment terminated.
- Why it matters: loss of P0-incident evidence and silent continuation of a stage the frozen amendment closed; the executable protocol contradicts the written one.
- Recommended correction: before resuming, record and commit a paired `verify_chain.sh` change (per amendment discipline): remove `dtmoe` from the default stage list and make the `dtmoe` case refuse to run; make `clean()` (or `task()`) never delete stems listed in `$V/MISMATCH.txt`; copy the three task-15 outputs to a read-only evidence directory. Reference this enforcement change from the amendment.

**2. P1 / Suspected issue — H800 qualification is under-specified and one reading is nonsensical; the failing configuration is not named.**
- Location: AMENDMENT_20261018b.md:19-21.
- Evidence: "qualified before the grid by two fresh-process runs of one L = 16 and one L = 32 development task that must be bit-identical" is ambiguous: two runs of each task compared pairwise (the only coherent reading), or one run per task compared to each other (impossible — different shapes). Which tasks/configurations are used is unspecified. The arbiter requires qualification to "cover relevant configurations/shapes, not merely pipeline names" and warns "two matching probes cannot establish universal determinism" (codex_nondeterminism.md:3, :9). The grid varies L, lr, steps, mech; only the L axis is covered, and the one configuration known to be non-reproducible (elec2 L32 lr1e-4 s1 m1, the task-15 config) is not required to be among the probes.
- Why it matters: if the main path (strict determinism) is taken on an under-scoped qualification and a later grid point is nondeterministic, single-run selection scores silently carry unquantified run noise, and the fallback the arbiter prescribed is skipped.
- Recommended correction: state explicitly — each qualification task is run twice in fresh processes and the two runs of each task must be bit-identical to each other (not to any local output); name the probe tasks and require them to include the task-15 configuration (elec2 L32 lr1e-4 s1 m1) and at least one further L=32 configuration with a different mech/lr; state that a single qualifying pair does not certify other grid points and that any later nondeterminism re-opens the fallback.

**3. P2 / Confirmed issue — PLAN.md clauses are not explicitly superseded; PLAN.md read alone still directs dtmoe continuation and a global stop.**
- Location: AMENDMENT_20261018b.md:14-25 vs. PLAN.md:22-25 (Order item 1), PLAN.md:29-33 (Stopping rule).
- Evidence: PLAN.md Order still lists "1. dtmoe development tasks 1-38 ... before any configuration is selected", and its stopping rule says two new runs disagreeing "stop GPU verification" with no stage scope — read literally this forbids resuming `confirm_cp` and directs the dtmoe stage to continue. The amendment overrides both but never enumerates which clauses it supersedes; `verify_chain.sh` comments cite PLAN.md only.
- Why it matters: a later session or operator applying the frozen PLAN.md literally re-opens dtmoe or keeps the whole chain stopped; the exception is supposed to be "narrow, explicit" (codex_nondeterminism.md:1).
- Recommended correction: add a short supersession list to the amendment: PLAN.md Order item 1 is cancelled; PLAN.md stopping rule applies unchanged except that the current two-disagreeing-replays event is resolved by closing the dtmoe stage (narrow exception) and does not stop the named remaining stages; everything else in PLAN.md stands.
