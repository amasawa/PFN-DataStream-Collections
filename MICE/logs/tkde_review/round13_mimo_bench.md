## Findings

1. **P1 | Suspected issue | CHILD attempt loop (`if "OutOfMemory" in p.stderr … rec["infeasible"]`) | Evidence: one OOM attempt permanently marks a (rep, policy, kmax, stream) infeasible and breaks the retry loop. `set_per_process_memory_fraction` only bounds the *allocator budget*; if the device is actually short of memory because a co-resident process holds part of it, `cudaMalloc` fails and torch raises `torch.cuda.OutOfMemoryError: CUDA out of memory`, which matches the same substring test. Registration B filters candidates by “feasible on all three prefixes”, so one spurious infeasible record excludes kmax 4 and silently forces k\*=2 (or an “over-budget fallback” label). | Correction: declare infeasible only after a confirmed quiet GPU (record `gpu_before`, require no foreign memory), or retry an OOM once after the `gpu_busy` wait; keep the first OOM stderr in the record either way.**

2. **P2 | Suspected issue | `gpu_busy()` / `gpu_state()` | Evidence: round 9 waited until `--query-compute-apps` listed no pid; here busy means util ≥ 5% **or** used ≥ 1500 MiB (idle baseline ~520 MiB). A foreign process holding <1 GiB at 0% util passes the gate, and contention that starts *during* the run and exits before `gpu_after` is invisible — the registered “GPU alone” condition is then not met and timings (and hence k\*) are contaminated. `gpu_state` is also recorded only *after* a success, never before. | Correction: also treat any non-empty compute-apps listing as busy when it works, tighten the memory threshold to idle + margin, and log `gpu_before` next to `gpu_after`.**

3. **P2 | Suspected issue | `main()` success path: `rec["gpu_after"] = gpu_state()` before `log.write` | Evidence: `gpu_state()` runs `nvidia-smi` and `assert q.returncode == 0`. If that query fails after the child already succeeded, the parent raises before `log.write`, so the cell has `.npz` + `.occ.json` but no record in `<stage>.jsonl`; the skip rule (`occ.json` exists → `continue`) then prevents re-measurement, and any analysis that reads the jsonl loses that timing permanently. | Correction: write the primary record first and append `gpu_after` separately, or make `gpu_state` failure non-fatal (`gpu_after: null`).**

4. **P2 | Confirmed issue | `main()` data preparation | Evidence: `n = 301 * 100` then `z["X"][:n]` with no check on source length; a source stream with fewer than 30 100 rows silently yields a prefix shorter than the registered batches 1–300, and nothing downstream reports the deviation (the child’s `T-1` assert is self-consistent with whatever was written). | Correction: `assert len(z["y"]) >= 301 * 100` for A1 sources (and log the resulting `T` per stream).**
