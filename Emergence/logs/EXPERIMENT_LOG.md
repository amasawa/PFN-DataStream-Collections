# Emergence 实验日志

本文件只记录"一个类在上下文里从 OOD 变成 ID（涌现）"这个方向的工作（来源：Zhilin Zhao 的 Confidence Amendment，TPAMI 2025；读了方法一节的开头和定理陈述）。目前只是可行性检查，没有立项。其他项目各有自己的日志。

## 2026-10-06 02:24：可行性检查的设计与判定规则（运行前写定；用户："做吧，两个都跑"）
- **设想**：流里一个新类刚出现时，上下文里没有它（应当拒识）；它的带标签的行一批批进入上下文后，逐渐变成应当分类的已知类。CA 的"OOD 逐步变成 ID、沿途修正置信度"在流里是真实的过程。要先知道：TFM 在这个过渡期里表现如何，是不是一个问题。
- **数据**：与 GrayContext 的检查相同的 9 个数据源当静态表用（只读 `MICE/data/`），5 个种子。每次试验指定一个"新类"c（按种子在保留的类里轮换）。上下文 1000 行，其中 n_c 行属于类 c，n_c ∈ {0, 1, 2, 5, 10, 20, 50, 100}，其余行来自其他类（按原比例）。测试 2000 行，其中 25% 属于类 c（对应新类出现之后的流），其余来自其他类。
- **量**（TabPFN v2，4 个 estimator）：
  - 新类行的召回率、旧类行的准确率、总体准确率、log-loss；
  - n_c = 0 时：用 1 − 最大概率区分"新类行/旧类行"的 AUROC（过渡期开始前的拒识能力）；新类行的平均最大概率；
  - 一个已有的简单修正作对照：用测试批上的 EM 估计类别先验并重加权（Saerens 等的 label-shift 校正，不需要标签），看它能补回多少。它对应"上下文里新类的比例远低于流里的比例"这一条解释。
- **判定规则（运行前写定）**：
  1. "问题存在"：n_c = 10 时，新类的召回率在 9 个数据源的平均上不超过 n_c = 100 时的 70%，且至少 6 个数据源如此；
  2. "问题没有被已有办法解决"：EM 先验校正在 n_c = 10 时补回的召回率差距（相对 n_c = 100）平均不到一半，或者它使旧类准确率平均下降 2 点以上。
  两条都满足才认为值得继续；只满足 1，说明问题存在但已有简单办法；1 不满足则放弃。
- **预期（运行前写下）**：n_c = 10 时召回率明显偏低（上下文里只有 1% 是新类，而测试里有 25%），规则 1 满足；EM 校正能补回相当一部分，规则 2 不一定满足——如果 EM 就够了，这个方向的新意要另找（例如标签延迟、EM 在新旧类条件分布重叠时失效的情形）。
- **脚本**：`code/check_emergence.py` → `results/emergence.csv`，可续跑。

## 2026-10-06 02:27：方向的来由与原文要点（补记；用户："好的记录到各个的log中"）
- **来由**：用户要求重读 Zhilin 的三篇 TPAMI 和 AIJ，看能否结合 Xiaoyu Yang 的思路做流。四篇的阅读笔记和三个结合方式的完整记录在 `GrayContext/logs/EXPERIMENT_LOG.md`（同日 02:22 一条）；这里只摘与本方向有关的部分。用户的决定："做吧，两个都跑"。
- **CA（Distilling the Unknown to Unveil Certainty，Zhao、Cao、Zhang、Lin、Zheng，TPAMI 47(10)，2025）读到的要点**（方法一节的开头与定理 1 的陈述；证明与实验没有读）：
  - 目标是从一个标准网络里蒸馏出对 OOD 敏感的二分类器 P_φ(c|x)。
  - 用一条参数化的马尔可夫链合成样本：x_0 取自高斯噪声（视为 OOD），之后每一步沿着提高网络置信度的方向移动，T 步后变成 ID 样本；有训练数据时加一个重构正则，没有时用先验正则。
  - "置信度修正"：链上第 t 步的样本，其预测分布与均匀分布按权重函数 α(t)=(t/T)^a 混合——越靠近 OOD 一端越接近均匀。
  - 定理 1：二分类器的泛化界通过 φ(a)=(a+1)(2a+1)/a² 依赖指数 a，φ 对 a 单调下降。
- **搬到流上的设想（Claude 的设想，尚无证据）**：CA 的链是"OOD 逐步变成 ID"。对 in-context 学习器，这个过程在流里真实发生：新类出现时上下文里没有它（应当拒识），随着它带标签的行进入上下文而变成已知类。链上的步数 t 对应上下文里该类的行数 n_c，α(t) 对应"随 n_c 增长的置信度修正日程"。TFM 特有的问题是 n_c 很小时它对这个类的预测和置信度是否可靠。
- **与 GrayContext 的关系**：新类刚出现时，它的行常被标成旧类，这正是"标签不可靠"的一种来源。两个方向可能合成一篇，也可能各自成文，等两边的可行性结果再定。
- **状态**：可行性检查 02:24 启动（tmux `emerg`），判定规则见上一条。
- **12:09 补充，中断与续跑**：可行性检查的输出停在 02:28（`h2_spam 0 done`，csv 208 行）；WSL 之后被重启，tmux `emerg` 丢失。12:09 起改为排在 GrayContext 的修复探查之后，在 tmux `gray` 里接着续跑（同一条命令，按已有行续跑）。

## 2026-10-06 12:42：可行性检查的结果（12:32 跑完；`results/emergence.csv`，9 个数据源 × 5 个种子）
- **按 n_c 的平均（%；新类召回 / EM 后新类召回 / 旧类准确率 / EM 后旧类准确率 / 总体 / EM 后总体）**：
  - n_c = 0：0.0 / — / 92.3 / — / 69.2 / —
  - n_c = 1：3.3 / 49.6 / 92.3 / 73.9 / 70.0 / 67.9
  - n_c = 2：5.2 / 70.8 / 92.3 / 58.5 / 70.5 / 61.5
  - n_c = 5：10.8 / 72.9 / 92.2 / 64.2 / 71.9 / 66.4
  - n_c = 10：18.8 / 64.8 / 92.2 / 80.5 / 73.9 / 76.6
  - n_c = 20：28.5 / 58.5 / 92.2 / 88.3 / 76.2 / 80.9
  - n_c = 50：43.4 / 63.6 / 92.0 / 88.7 / 79.8 / 82.4
  - n_c = 100：55.6 / 65.8 / 91.2 / 88.9 / 82.3 / 83.1
- **规则 1 成立**：n_c = 10 时的召回率是 n_c = 100 时的 0.24（门槛 ≤ 0.70），9 个数据源中 8 个满足（需要 6 个）。
- **规则 2 成立，但只靠"或"的后一半**：EM 先验校正在 n_c = 10 时补回差距的 1.25 倍（远高于 0.5，即召回差距被补回了），但旧类准确率下降 11.69 点（门槛 2 点）。
- **判定：两条都满足，按规则值得继续。** 与预期一致："EM 能补回相当一部分，规则 2 不一定满足"——它是靠旧类准确率的代价才满足的。
- **更具体的读法（Claude 的判断）**：EM 在 n_c ≥ 10 时总体准确率是净收益（n_c = 10：73.9 → 76.6），在 n_c ≤ 5 时是净损失（n_c = 2：70.5 → 61.5）。没有被已有办法解决的窗口是新类只有几行的时候，这与 CA 的"随 n_c 增长的置信度修正日程"的设想是对得上的。
- **两处要打折**：
  - EM 的平均值 1.25 被 h2_airlines 拉歪：这个数据源的新类召回率几乎恒为 0（n_c = 100 时 0.4），分母接近零，单项算出 112.0。去掉它，其余 8 个的平均是 1.18，结论不变。
  - n_c = 0 的拒识结果（平均 AUROC 57.4）里有 5 个数据源恰好是 0.500、置信度 1.000（elec2、h2_airlines、h2_phishing、h2_spam、h2_weather），推测是二分类数据去掉一类后上下文只剩一个类，属于退化情形；有信息量的只有 covertype 0.703、h2_poker 0.735、h2_rialto 0.749、insects 0.475。这一点是从数字推断的，还没有回脚本核实。
